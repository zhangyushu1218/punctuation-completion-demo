# 标点符号标注逻辑说明

## 核心设计理念

本模型采用**序列标注（Sequence Labeling）**的方式进行标点预测，而非直接生成带标点的文本。

## 数据处理流程

### 1. 训练阶段

#### 步骤1: 文本清洗 (`clean_raw_text`)
- **输入**: 原始带标点文本
- **输出**: 保留汉字、字母、数字和目标标点的文本
- **示例**: 
  ```python
  输入: "你好，世界！@#$%"
  输出: "你好，世界！"
  ```

#### 步骤2: 构建标签序列 (`build_punct_label_sequence`)
- **输入**: 清洗后的带标点文本
- **输出**: 
  - `src`: 移除所有标点后的纯文本
  - `labels`: 与原文本字符一一对应的标签序列
- **关键逻辑**: 
  - 标点符号本身**不保留**在 src 中
  - 标点符号的标签标记在**前一个字符**的位置上
  - 非标点字符的标签为 "O"

- **示例**:
  ```python
  输入: "你好，世界。"
  
  处理过程:
  - '你' -> 添加到src, 标签"O"
  - '好' -> 添加到src, 标签"O"
  - '，' -> 不添加到src, 将前一个字符('好')的标签改为"COMMA"
  - '世' -> 添加到src, 标签"O"
  - '界' -> 添加到src, 标签"O"
  - '。' -> 不添加到src, 将前一个字符('界')的标签改为"PERIOD"
  
  输出:
  src = "你好世界"
  labels = ["O", "COMMA", "O", "O", "PERIOD"]
  ```

#### 步骤3: Tokenization (`tokenize_and_align_labels`)
- 将 src 文本转换为 token IDs
- 将 labels 对齐到 tokens
- padding 部分使用 -100 忽略

### 2. 推理阶段

#### `infer_punctuation` 函数逻辑

```python
for each character in input_text:
    1. 添加字符到结果
    2. 查看该字符位置的预测标签
    3. 如果标签 != "O":
       在字符后插入对应的标点符号
```

**示例**:
```python
输入: "你好世界"
预测标签: ["O", "COMMA", "O", "O", "PERIOD"]

处理过程:
- '你' (标签"O") -> 添加"你"
- '好' (标签"COMMA") -> 添加"好" + "，"
- '世' (标签"O") -> 添加"世"
- '界' (标签"PERIOD") -> 添加"界" + "。"

输出: "你好，世界。"
```

## 特殊标点处理

### 冒号（：）
- 训练时：冒号被移除，标签标记在前一个字符上
- 推理时：在预测为 COLON 的字符后插入冒号

**示例**:
```python
训练: "他说：" -> src="他说", labels=["O", "COLON"]
推理: "他说" + COLON标签 -> "他说："
```

### 双引号（"" / ""）
- **左引号**: 标记在前一个字符后
- **右引号**: 标记在前一个字符后

**示例**:
```python
训练: "他说："你好"" 
-> src="他说你好"
-> labels=["O", "COLON", "QUOTE_LEFT", "QUOTE_RIGHT"]

推理: "他说你好" + 对应标签
-> "他说："你好""
```

## 常见误解

### ❌ 错误理解
认为 `build_punct_label_sequence` 应该保留冒号和引号在 src 中。

### ✅ 正确理解
**所有标点符号**（包括逗号、句号、顿号、感叹号、问号、冒号、分号、双引号）在训练时都会被从 src 中移除，只通过标签来表示它们的位置和类型。

## 测试用例说明

### test_clean_raw_text
测试文本清洗功能，期望**保留**所有目标标点：
```python
("他说：\"你好\"", "他说：\"你好\"")  # ✓ 正确
```

### test_build_punct_label_sequence
测试标签序列构建，期望**移除**所有标点：
```python
("他说：\"你好\"", "他说你好", ["O", "O", "COLON", "QUOTE_LEFT", "O", "O", "QUOTE_RIGHT"])  # ✓ 正确
```

## 为什么这样设计？

1. **统一的标注框架**: 所有标点都通过相同的方式处理（标记在前一个字符上）
2. **简化模型输出**: 模型只需要对每个位置输出一个标签，无需考虑标点是否保留
3. **灵活的插入机制**: 推理时可以灵活地在任意位置插入标点
4. **符合 BERT 架构**: Token Classification 天然适合这种逐token标注的任务

## 注意事项

⚠️ **重要**: 
- 如果某个标点前面没有字符（如文本以标点开头），该标点会被忽略
- 连续标点只会保留最后一个（通过 `clean_raw_text` 中的正则处理）
- 双引号的配对通过后处理函数 `post_process_punctuation` 确保
